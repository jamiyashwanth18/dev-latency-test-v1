<!-- sdlc:auto:start overview -->
Dev latency test - v1 is a small-team leave management app generated by the Quorq AI SDLC platform, structured as two separate applications in one repository. The frontend is a Vite + React 19 single-page app whose screens (sign-in by picking an identity, My Leave, Approvals, Team Calendar, Administration) were design-approved and currently render seeded sample data rather than calling the API. The backend is a FastAPI 0.115 service backed by SQLAlchemy models and Alembic migrations (PostgreSQL in deployment, SQLite locally by default) that currently implements identity/session endpoints, admin user management, and leave-request submission/listing, enforcing all role rules server-side.

<!-- sdlc:auto:start setup -->
1. Clone the repository and cd into it.
2. (Optional) Start a local PostgreSQL database: `docker compose up -d` (exposes Postgres on localhost:5432 as configured in docker-compose.yml). If skipped, the backend falls back to a local SQLite file ./app.db.
3. Copy `.env.example` to `.env` and set the variables documented in backend/README.md (DATABASE_URL, ALLOWED_ORIGINS, SECRET_KEY, JWT_SECRET_KEY, MEDIA_ROOT, BOOTSTRAP_ADMIN_EMAIL/BOOTSTRAP_ADMIN_PASSWORD, SMOKE_TEST_EMAIL/SMOKE_TEST_PASSWORD) using placeholder values of your own.
4. Set up the backend: `cd backend && pip install -r requirements.txt`.
5. Run the backend: `uvicorn app.main:app --reload` (applies Alembic migrations and seeds platform accounts on startup).
6. In a separate terminal, set up the frontend: `cd frontend && npm install`.
7. Run the frontend: `npm run dev`.
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one FastAPI router per API component/entity group under app/routers, included in app/main.py as implemented.
- Backend: SQLAlchemy models (app/models.py) and Pydantic request/response schemas (app/schemas.py) are kept separate; enums use StrEnum.
- Backend: all primary keys are UUIDs generated in Python (default=uuid.uuid4); dialect-neutral column types (Uuid, JSON/JSONB variant) so the same models run on PostgreSQL and SQLite.
- Backend: the session/token model is named UserSession (not Session) to avoid shadowing sqlalchemy.orm.Session.
- Backend: the schema is only ever changed via Alembic migrations; app.main runs `alembic upgrade head` on startup via run_migrations().
- Backend: role checks (employee/manager/hr_admin) are enforced server-side in route handlers/dependencies, never trusted from the client.
- Backend: platform account seeding (seed.py) is idempotent — users are created only if no user with that email already exists.
- Frontend: one module per approved screen under src/screens; shared UI building blocks in src/lib/ui.tsx and icons in src/lib/icons.tsx; brand tokens in src/lib/brand.ts and index.css.
- Frontend: all API calls are expected to go through the single apiFetch helper in src/lib/api.ts, which attaches the bearer session token and normalizes errors as ApiError.
- Frontend: component tests live beside the component they cover (e.g. Admin.test.tsx next to Admin.tsx); Playwright e2e specs live in e2e/ separate from Vitest's scope.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start or can't reach the database. | If DATABASE_URL is unset, the backend defaults to a local SQLite file (./app.db), so no server is required; if you intend to use PostgreSQL, start it first (e.g. `docker compose up -d`) and set DATABASE_URL in .env. |
| Frontend calls to the API are blocked by the browser (CORS). | Set ALLOWED_ORIGINS in the backend's environment to include the frontend's origin (defaults to the Vite dev server's origin if unset). |
| `npm run build` succeeds but `tsc` would have failed. | `npm run build` does not typecheck; run `npm run typecheck` separately to catch type errors before relying on a build. |
| Running `pytest` from an unexpected directory fails to import `app`. | Run pytest from backend/ (pytest.ini sets `pythonpath = .` relative to that directory). |
| Playwright e2e tests fail immediately with a missing browser error. | Run `npm run test:e2e:install` once before `npm run test:e2e`. |
| No users appear in the sign-in identity picker. | Ensure BOOTSTRAP_ADMIN_EMAIL/BOOTSTRAP_ADMIN_PASSWORD and/or SMOKE_TEST_EMAIL/SMOKE_TEST_PASSWORD are set in the backend environment; seeding only creates an account when both of a pair are set and no user with that email exists yet. |
<!-- sdlc:auto:end troubleshooting -->
