<!-- sdlc:auto:start overview -->
Dev latency test - v1 is a small-team leave management app generated by the Quorq AI SDLC platform, structured as two independently runnable pieces in one repo. The frontend (frontend/) is a Vite + React 19 single-page app whose screens were generated from an approved design and currently render seeded sample data rather than calling the API. The backend (backend/) is a FastAPI 0.115 service with SQLAlchemy models, Pydantic schemas, Alembic-managed PostgreSQL/SQLite schema, and routers implementing session-based sign-in (pick-a-user, no password), leave request submission/approval, balance calculation, and HR/Admin user management, with role checks enforced server-side. Deployment (see .github/workflows/deploy.yml) builds a Docker image for the backend and publishes the frontend to AWS Amplify, but that workflow is informational only for local development.

<!-- sdlc:auto:start setup -->
1. Clone the repository and cd into it.
2. (Optional) Start a local PostgreSQL database: `docker compose up -d db` -- otherwise the backend falls back to a local SQLite file (./app.db).
3. cd backend && pip install -r requirements.txt
4. Start the backend: `uvicorn app.main:app --reload` -- on startup it runs Alembic migrations (`alembic upgrade head`) and seeds platform accounts if BOOTSTRAP_ADMIN_EMAIL/BOOTSTRAP_ADMIN_PASSWORD and/or SMOKE_TEST_EMAIL/SMOKE_TEST_PASSWORD are set in the environment.
5. In a second terminal, cd frontend && npm install
6. Start the frontend: `npm run dev`
7. Open the Vite dev server URL in a browser; sign in by picking a seeded user (no password).
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- One FastAPI router per feature area, included in app/main.py as it is implemented; routes are added incrementally per ticket.
- Pydantic schema naming reflects audience/purpose: *Public (safe-to-return shape), *Create/*Update (request bodies), *Response (full response).
- Role checks (employee/manager/hr_admin) are enforced server-side via FastAPI dependencies (e.g. _require_hr_admin), never trusted from the frontend.
- SQLAlchemy models use dialect-neutral types (Uuid, JSON().with_variant(JSONB, 'postgresql')) so the same models run on PostgreSQL and the local SQLite fallback.
- Schema changes are made only through Alembic migrations in backend/migrations, applied automatically via run_migrations() in the app's lifespan.
- Startup seeding (app/seed.py) is idempotent: a user is created only if no user with that email already exists.
- Frontend screens live one-per-file under src/screens with a colocated *.test.tsx; shared primitives live in src/lib.
- The frontend API client (src/lib/api.ts) centralizes base URL, bearer token storage (localStorage), and error handling (ApiError) for all backend calls.
- Backend tests are split into tests/unit and tests/integration, both exercising a real database rather than mocks.

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend fail with a CORS error in the browser console. | Set ALLOWED_ORIGINS on the backend to include the frontend's origin (defaults to the Vite dev server's origins if unset). |
| Backend fails to start because it can't reach PostgreSQL. | Either start the local database with `docker compose up -d db` and set DATABASE_URL accordingly, or unset DATABASE_URL to fall back to the local SQLite file ./app.db. |
| No admin or employee account is seeded on startup, so there's nothing to sign in as. | Set BOOTSTRAP_ADMIN_EMAIL and BOOTSTRAP_ADMIN_PASSWORD (both required) for the HR/Admin account, and/or SMOKE_TEST_EMAIL and SMOKE_TEST_PASSWORD for the employee account, before starting the backend. |
| `npm run build` succeeds but the app is actually type-broken. | `npm run build` does not typecheck; run `npm run typecheck` (tsc --noEmit) to catch type errors before deploying. |
| `npm run test:e2e` fails immediately with a missing-browser error. | Run `npm run test:e2e:install` once to fetch the Chromium binary Playwright needs. |
| Running `pytest` from a directory other than backend/ fails with `ModuleNotFoundError: app`. | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` puts app/ on sys.path. |
<!-- sdlc:auto:end troubleshooting -->
